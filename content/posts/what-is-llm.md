## 밀가루 반죽 같은 것이라고 생각해보세요

파운데이션 모델을 가장 쉽게 떠올리는 방법은 반죽입니다. 밀가루 반죽 하나로 빵도 만들고, 피자도 만들고, 만두피도 만들 수 있습니다. 반죽을 만들 때부터 "이건 빵 전용, 저건 피자 전용"으로 나누지 않습니다. 일단 크고 무난한 반죽을 만들어 놓고, 그때그때 필요한 모양으로 빚어 씁니다.

예전 AI는 그렇지 않았습니다. 번역기, 스팸 분류기, 감정 분석기를 각각 처음부터 따로 만들었습니다. 재료도 따로 모으고, 학습도 따로 하고, 관리도 따로 했습니다. 하나 더 만들고 싶으면 또 처음부터였습니다.

지금은 순서가 뒤집혔습니다. 아주 방대한 글과 코드, 대화를 재료 삼아 커다란 반죽을 한 번 만들어 놓습니다. 그 반죽 위에서 번역도 시키고, 요약도 시키고, 초안 작성도 시킵니다. 바닥에 깔린 반죽이라는 뜻으로 이걸 파운데이션 모델이라고 부릅니다. 그중 말(텍스트)을 다루는 반죽이 LLM(Large Language Model)입니다. 이미지나 음성을 다루는 반죽도 따로 있습니다.

## LLM은 정확히 무엇을 하고 있나

LLM이 하는 일을 한 문장으로 줄이면, 다음에 올 말을 확률로 골라 이어 붙이는 일입니다. 아주 많은 글을 읽어서 "이런 문장 다음에는 대체로 이런 말이 온다"는 감각을 익힌 사람이, 그 감각만으로 문장을 이어 쓰는 것과 비슷합니다.

이 비유가 중요한 이유는, 사람들이 흔히 기대하는 것과 실제 동작이 다르기 때문입니다.

| 사람들이 기대하는 것 | 실제로 일어나는 일 |
| --- | --- |
| 어딘가에 있는 정답을 찾아온다 | 학습한 패턴으로 그럴듯한 다음 말을 이어 붙인다 |
| 최신 뉴스를 실시간으로 안다 | 검색 기능이 없으면 학습이 끝난 시점 이후 일은 모른다 |
| 계산기처럼 항상 정확하다 | 코드 실행 기능이 없으면 큰 계산에서 틀리기 쉽다 |
| 모르면 모른다고 한다 | 모를 때도 자연스러운 문장으로 답할 수 있다 |

그래서 LLM의 답을 볼 때는 "이게 사실인가"와 "이게 말이 되는가"를 따로 확인하는 습관이 필요합니다. 둘은 다른 질문입니다.

## 모델과 서비스는 다른 것이다

반죽과 완성된 빵이 다르듯, 모델과 우리가 실제로 쓰는 서비스(ChatGPT, Claude 같은 앱)는 다른 것입니다. 같은 반죽이라도 어떤 오븐에서, 어떤 온도로, 어떤 재료를 곁들여 굽느냐에 따라 완전히 다른 빵이 나옵니다.

서비스도 마찬가지입니다. 안에 있는 LLM에 검색 기능을 붙이거나, 대화 기록을 기억하게 하거나, 답변 말투를 다듬는 등 여러 겹을 씌워서 하나의 서비스로 내놓습니다. 그래서 "이 모델이 저 모델보다 낫다"는 이야기가 사실은 모델 자체의 차이가 아니라, 감싸고 있는 서비스의 차이인 경우가 많습니다.

## 그래서 오늘부터 무엇을 다르게 하나

이름의 차이를 알았으면 실전에서 써먹을 차례입니다.

지금 쓰는 서비스에서 검색 기능을 켜고 끈 상태로 같은 질문을 비교해 보세요. 모델 혼자 아는 것과 도구가 채워주는 것의 차이가 눈으로 보입니다. 숫자나 최신 정보가 걸린 질문이면 검색이 켜져 있는지부터 확인하는 게 순서입니다.

파일이 여러 개 걸린 작업이라면 채팅창에 하나씩 복사해 붙이지 말고, 작업 폴더를 통째로 공유해서 실행해보세요. 요즘 나오는 코딩 도구들은 폴더를 그대로 넘겨받아 파일 사이의 맥락을 스스로 찾아 씁니다. 검색, 파일 읽기, 코드 실행 같은 기능이 반죽 위에 하나씩 붙을수록, 그냥 대답만 하는 도구에서 실제로 일을 대신 처리해주는 도구로 성격이 바뀝니다. 이렇게 일하는 방식을 부르는 이름이 에이전트입니다. 다음 글 [챗봇과 에이전트는 무엇이 다른가](/posts/chatbot-vs-agent)에서 이어서 다룹니다.
